# 用户手册

## 1. 首次启动

1. 打开应用，进入欢迎页。
2. 选择服务商（推荐 **DeepSeek**）。
3. 粘贴 API Key（眼睛图标可切换显示）。
4. 模型默认 `deepseek-flash`，可保持默认或输入自己的模型 ID。
5. 点击 **测试连接**。看到“收到真实文本回复”才算成功。
6. 点击 **保存并开始聊天**。

暂时没有 Key 可以点“暂时跳过”浏览应用，但聊天前必须配置模型。

## 2. 对话

- 默认是 **普通对话**：只调用语言模型，不需要 Shizuku、无障碍、MCP 或任何设备权限。
- 输入框支持多行；发送后按钮变为停止。
- 生成过程中可以随时 **停止**，已生成的部分会保留并标记“已停止生成”。
- 助手回复底部有 **复制** 和 **重新生成**。
- 顶部可打开 **历史对话**，切换或删除会话。
- 顶部显示当前模型；点击可进入模型管理。
- 出错时显示具体原因（Key、地址、模型、限流、网络等），并提供重试与“打开模型设置”。

## 3. Agent 模式

在对话页顶部切换到 **Agent 模式** 后发送消息：

- 会创建一个独立的 Agent 任务，可在「任务」页查看计划、工具调用、审计事件、检查点和产物。
- 高风险操作（ADB 命令、删除文件、发送截图到云端、运行脚本）会弹出确认框。
- 普通聊天与 Agent 任务的记录互不混用。

## 4. 任务

- 列表只显示 Agent 任务；普通对话在「对话 > 历史」中。
- 任务详情：执行计划、工具调用、事件、检查点、产物、最终回复。
- 支持停止、恢复、导出 Markdown。
- 应用被系统杀死后，进行中的任务会变为“已暂停”，不会自动重复执行；需要用户手动恢复，恢复时模型会先校验副作用。

## 5. 终端

- **应用 Shell**：以应用 UID 执行，无 root、无 ADB。
- **Shizuku（ADB）**：需安装并启动 Shizuku，授予本应用权限；以 shell UID 执行。
- 显示 stdout、stderr、退出码、耗时，可取消。
- 破坏性命令（`rm -rf /`、`mkfs`、写入块设备等）会被硬拦截。

## 6. 模型管理

- 每个模型卡片显示：服务商、模型 ID、连接状态、已验证能力（文本/流式/工具调用等）、最近测试时间。
- 只有测试真正验证过的能力才会显示；未测试显示“未测试”。
- 可设为默认、编辑、重新测试、删除（同时删除保存的 Key）。

## 7. 语言

「我的 > 语言」可切换：跟随系统 / 简体中文 / English。

主流程（导航、对话、模型、首次配置、设置、任务、终端、我的）已使用标准资源；
MCP、技能、诊断、工作区等页面仍有部分旧文案未完全资源化，属于已知遗留。

## 8. 进阶能力（可选）

- **Shizuku**：安装 Shizuku → 开启无线调试并配对 → 启动 → 在应用内授权。
- **无障碍**：系统设置中启用 “Mobile Agent automation”，再在应用「我的 > 无障碍」中确认连接。
- **MCP**：添加 Streamable HTTP 端点，连接后工具会出现在 Agent 可用列表中。
- **技能**：内置 6 个技能；可导入 zip（SKILL.md + skill.yaml）。
- **定时任务**：Agent 可创建，或在任务页查看；最小间隔 15 分钟，受 Doze 影响。

## 9. 常见问题

| 现象 | 处理 |
| --- | --- |
| 提示 API Key 无效 | 重新复制 Key；确认没有多余空格；测试连接查看鉴权阶段。 |
| 提示模型不存在 | 检查模型 ID（DeepSeek 当前为 `deepseek-flash` / `deepseek-v4-pro`）。 |
| 提示网络/DNS | 检查网络、代理、VPN；测试连接会区分网络与鉴权。 |
| 一直“正在生成” | 可点停止；若反复发生，检查流式开关与网络。 |
| Agent 任务没有工具 | 确认模型支持工具调用，并在模型高级设置中开启“工具调用”。 |
| 截图/界面操作失败 | 检查无障碍服务是否连接，受保护窗口无法截图。 |
| 单元测试初始化失败 | Windows 中文路径的 Gradle `@argfile` 问题，使用 `scripts/run-tests-ascii.ps1`。 |
